# 数据治理与安全边界

## 数据分类

| 类别 | 仓库当前状态 | 使用要求 |
| --- | --- | --- |
| 景点/活动知识 | 原创合成数据 | 标注 `synthetic://`，仅用于演示和测试 |
| 价格与时间 | 原创合成数值/文本 | 不能作真实报价、营业时间或安全建议 |
| 用户输入 | 演示请求参数 | 不放入真实姓名、联系方式、订单、证件或支付信息 |
| 工单 | 本地模拟记录 | 不代表真实 CRM 或客服处理 |
| 模型密钥 | 不应存在于仓库 | 仅通过本地环境变量/密钥管理工具注入，绝不提交 |

## 来源链

当前数据链被刻意设计得简单且可审计：

```text
仓库维护者原创合成条目
          ↓
data/attractions.json
          ↓
data/sources_manifest.json（数据集版本、来源 ID、权利说明）
          ↓
API citation / source_url（synthetic:// ID）
          ↓
评测与演示报告
```

链路中的 `synthetic://` 不是外部网站，不能被当作外部权威来源引用。

## 真实数据接入清单

在把演示数据替换为公开或合作方数据前，需要逐项完成：

1. **授权与许可**：确认数据来源许可、API 条款、保存期限和再分发限制；
2. **最小化采集**：只取完成功能所需字段，不采集不必要的个人或订单信息；
3. **来源快照**：记录来源 URL、抓取/同步时间、解析器版本、许可说明和数据版本；
4. **准确性与更新**：定义失效期、更新频率、下架和纠错流程；
5. **个人信息**：完成数据分类、脱敏、访问控制、日志清理和删除请求流程；
6. **输出安全**：将“参考信息”与“可交易承诺”区分，提供人工确认路径；
7. **评测隔离**：用不含敏感数据的评测集做回归，禁止把真实用户输入直接写进 Git。

## 安全设计的最低要求（未来接入外部系统时）

- 身份认证与基于角色的授权；
- API Key 使用环境变量或密钥管理服务，配置文件只提交示例；
- 请求体大小限制、字段长度限制、速率限制和审计日志；
- 日志不记录令牌、Authorization、完整姓名/电话/订单信息；
- 对写操作引入幂等键、人工审批/确认和失败重试策略；
- 对 LLM 工具调用设置 allowlist、JSON schema 校验、超时和最小权限；
- 定期审查依赖漏洞与容器基础镜像。

本 PoC 并未实现这些生产控制，不应暗示已经具备生产合规性。
