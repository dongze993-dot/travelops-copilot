# 演示与面试验收清单

## 录屏前（约 3 分钟）

- [ ] 新建干净虚拟环境或容器，确认没有依赖本机私有文件；
- [ ] `GET /health` 返回成功；
- [ ] 打开 `/docs`，展示输入与输出结构；
- [ ] 用 `杭州 + 自然 + 2 天 + 预算` 跑一次正常规划；
- [ ] 展示响应内的 `citations`、`validation` 和 `workflow_trace`；
- [ ] 用一个超低预算或无覆盖目的地展示诚实的失败/降级路径；
- [ ] 创建并查询一张**模拟**工单，口头说明未连接真实 CRM；
- [ ] 运行评测，保留原始报告；
- [ ] 检查终端、请求和录屏中没有 API Key、真实姓名、电话、订单或路径隐私。

## 面试时能讲清的五件事

1. **问题怎么拆**：把行程请求拆成检索、规划、约束校验、人工交接，而非让模型自由发挥。
2. **数据从哪来**：当前全是原创合成数据；每条数据都有 manifest 和 `synthetic://` ID。
3. **为什么用结构化 JSON**：前端、CRM、评测工具都能稳定消费，错误也更容易定位。
4. **怎么验收**：评测集与 HTTP 黑盒脚本检查输入边界、来源、预算、工单和 API 契约；没有报告就不报指标。
5. **距离生产还差什么**：真实数据授权、认证、隐私、幂等、监控、真实系统对接与模型安全。

## 可能被追问的问题

| 追问 | 可诚实回答的方向 |
| --- | --- |
| 为什么不直接做一个聊天页面？ | 聊天是界面，交付难点在数据边界、JSON 契约、校验、异常和可追溯性。 |
| 这是 RAG 吗？ | 当前是受控知识检索与来源返回的最小实现；如果接入向量检索/LLM，要补切分、召回评测、提示词和事实边界。 |
| 为什么不接真实旅游数据？ | 本项目优先展示架构和交付链路。真实数据涉及许可、准确性、更新与用户风险，未经授权不应伪造接入。 |
| 工单真的写到 CRM 了吗？ | 没有。它是模拟适配器，用来证明接口契约和工作流位置；真实 CRM 需要 OAuth/密钥、字段映射、幂等和审批。 |
| 指标是多少？ | 先展示当次报告、命令、数据版本和失败项；只谈该环境下的 API 契约结果，不把它外推为业务效果。 |
