# ADR-0003：把联网网页检索做成独立、可关闭的 v3 路径

- 状态：Accepted
- 日期：2026-09-21

## 背景

项目的 v1/v2 只读取仓库中的少量合成景点资料。未知城市应返回空覆盖/人工确认，而不是借用别城资料或编造景点。因此它不能满足“任意中国城市都给出联网来源”的演示需求。

DeepSeek 在本项目中可作为受约束的文本生成器，但其通用 Responses API 不能直接当作网页搜索工具。需要单独的检索提供方，并且要避免把访问者输入、Key 或未经核验的网页事实扩散到公开前端。

## 决策

新增 Netlify Functions v3：

- `GET /api/v3/live-attractions`：只含目的地/偏好、允许短时 CDN 缓存的来源检索；
- `POST /api/v3/live-plans`：以同次来源的 ID 组织候选日程；
- Tavily Key 仅在函数运行时环境变量中读取；
- 输入只投递目的地和选中的偏好，拒绝非空备注与工单创建；
- 输出只保留清洗后的 `https` URL、标题、短摘要、来源 ID、获取时间和缓存状态；
- 价格、开放时间、交通、预约和可订性均标为待核验，预算仅是用户预算上限的分配框架；
- v1/v2 与浏览器静态演示保持原样，不将“合成”静默变为“联网”；
- v3 缺 Key、鉴权失败、限流、超时或无结果时 fail closed，不回退为伪装成联网的合成结果；
- 每个 v3 函数设置 `3 次 / 分钟 / IP` 的 Netlify 函数限流；GET 来源端点设置短时 CDN 缓存。

## 后果

优点：

- 任意城市查询有真实网页来源的机会，来源可由演示者点击核验；
- 外部 API、数据最小化、HTTP 错误分级、缓存、限流、前端状态和离线 fake-provider 测试都可在仓库中审查；
- 不用把个人 DeepSeek Key 暴露给公开访客。

代价与未完成项：

- 搜索引擎的地区覆盖、内容时效和来源质量不是本项目可保证的；
- 每 IP 限流和 CDN 缓存不足以保护全站免费额度；在公开给大量访客前，仍需要基于 Netlify Blobs 或其他共享存储的日/月额度控制；
- 本阶段不调用 DeepSeek 生成 v3 文本，避免在无鉴权公开端点上消耗个人模型额度。未来如接入，必须把模型可见字段限制为已清洗来源，并验证每一项引用；
- 检索结果不是票务、报价、导航或安全服务。

## 验证

`tests/live_retrieval.test.mjs` 完全使用 fake provider：验证未知城市（例如上饶）能规范化为可点击来源、敏感备注不会出站、缺 Key 时 503、供应商错误不泄露 Key、缓存语义、价格不被伪装为 `¥0`，以及 v3 函数限流配置存在。
